# Архитектурный документ: Link Checker

## Цель
Реализовать веб-сервер, соответствующий [ТЗ](./TS.md), с:
- проверкой доступности URL,
- присвоением уникального `links_num` каждому набору,
- генерацией PDF-отчёта по списку `links_num`,
- *graceful shutdown* с сохранением состояния,
- файловой персистентностью (без внешней БД).

## Общие принципы

1. **Разделение ответственности**  
   Каждый компонент делает строго свою работу и не лезет в чужую.

2. **Зависимости через интерфейсы**  
   Компоненты объявляют, какие операции им нужны (интерфейсы), 
   а не требуют конкретных реализаций. Например, `service` работает 
   с хранилищем, умеющим `Save/Load`, а не с конкретным `storage`.

3. ***Graceful shutdown***  
   Завершённые задачи (`links_num` выдан) сохраняются на диск. Аварийные сбои зависят
   от реализации хранилища. Запросы поступившие в момент завершения получают ответ `503`.
   Бизнес-логика не участвует в завершении работы.


## Компоненты и их обязанности

### 0. cmd/app
- **Ответственность:** точка входа.
- **Делает:**
    - Загружает конфигурацию.
    - Создает экземпляр `internal/app.App`.
    - Вызывает `app.Run()`.
    - При ошибке - завершается с `log.Fatal`.
- **Не делает:** ничего больше. Никакой логики сборки, зависимостей, сигналов.

### 1. internal/app
- **Ответственность:** оркестрация жизненного цикла приложения.
- **Делает:**
    - Получает конфигурацию.
    - Создает `storage`, `checker`, `report.Builder`, `service`, `api`, `server`.
    - Подписывается на `SIGINT`/`SIGTERM`.
    - При сигнале: инициирует graceful shutdown через `server`.
- **Не делает:** не содержит бизнес-логики, не знает форматов данных.

### 2. internal/server
- **Ответственность:** управление жизненным циклом HTTP-сервера и отказ в обслуживании новых запросов во время *shutdown*.
- **Делает:**
    - Оборачивает `http.Handler` (от `api`) во внутренний *middleware*, который отклоняет новые запросы с `503`, если сервер в состоянии shutdown.
    - Предоставляет метод `Shutdown(ctx)` -> устанавливает флаг shutdown -> вызывает `http.Server.Shutdown()`.
    - Предоставляет метод `ListenAndServe()`.
- **Не делает:** не знает о бизнес-логике, не парсит тело запроса, не вызывает `service`.

Примечание: Middleware для shutdown - часть `server`, не выносится в `api`.

### 3. internal/api
- **Ответственность:** преобразование HTTP-запросов в вызовы сервиса и обратно.
- **Делает:**
    - Десериализует JSON из `/check-links` и `/get-report`.
    - Вызывает методы `service.LinkChecker` и `service.Reporter`.
    - Сериализует ответ (`application/json` или `application/pdf`).
    - Возвращает HTTP-статусы при ошибках.
- **Не делает:**
    - Не управляет состоянием shutdown.
    - Не работает с файлами.
    - Не проверяет URL напрямую.
    - Не генерирует PDF.

Примечание: Зависит только от интерфейсов `LinkChecker` и `Reporter`.

### 4. internal/service
- **Ответственность:** оркестрация бизнес-логики - координирует `storage`, `checker`, `report`.
- Реализует интерфейсы:
    - `LinkChecker`: принимает список URL -> проверяет через `checker` -> сохраняет результат в `storage` -> возвращает `LinkSet` с ID.
    - `Reporter`: принимает список ID -> загружает соответствующие `LinkSet` из `storage` -> передает данные в `report.Builder` -> возвращает `Report`.
- **Не делает:**
    - Не знает о HTTP.
    - Не управляет graceful shutdown.
    - Не читает/пишет файлы напрямую (делегирует `storage`).

### 5. internal/checker
- **Ответственность:** конкурентная проверка доступности URL.
- **Делает:**
    - Принимает `[]string` (сырые URL).
    - Валидирует и нормализует (добавляет `http://` при необходимости).
    - Выполняет конкурентные `HEAD`-запросы с таймаутом.
    - Возвращает `map[string]bool` или `[]Link` (статус на каждый URL).
- **Не делает:**
    - Не сохраняет результаты.
    - Не генерирует ID.
    - Не знает о `storage` или `service`.

### 6. internal/storage
- **Ответственность:** хранение и восстановление данных (`LinkSet` и `links_num`).
- **Делает:**
    - Генерирует уникальный 64-битный `links_num` для каждого нового набора.
    - Читает данные с диска по требованию (лениво).
    - Может использовать ограниченный in-memory кэш, но не обязан хранить всё состояние в памяти.
    - Обеспечивает, что каждый завершённый набор в **конечном счёте** сохраняется на диск.
    - Предоставляет метод `Close()`, который гарантирует, что все данные, накопленные к моменту вызова, будут сохранены на диск до выхода из метода.

- **Не делает:**
    - Не проверяет URL.
    - Не генерирует PDF.
    - Не знает о HTTP или graceful shutdown.

### 7. internal/report
- **Ответственность:** генерация PDF-отчёта из готовых данных.
- **Делает:**
    - Принимает `[]LinkSet`.
    - Формирует PDF с читаемой структурой (заголовок по ID, список URL + статус).
    - Возвращает `io.Reader` + `ContentType: application/pdf`.
- **Не делает:**
    - Не читает файлы.
    - Не обращается к `storage`.
    - Не знает о `links_num` как идентификаторе запроса - работает только с данными.

### 8. internal/model
- **Ответственность:** общие типы данных, используемые между слоями.
- Содержит:
    - `Link`, `LinkSet`, `Report` и ошибки приложения.
    - Все структуры - чистые данные, без методов/логики.

## Потоки данных

### /check-links
HTTP -> api -> service.CheckLinks ->
    checker.Check ->
    storage.Save (присваивает ID) ->
    api <- service <- storage

### /get-report
HTTP -> api -> service.Report ->
    storage.Load(IDs...) ->
    report.Build([]LinkSet) ->
    api <- service <- report

### Graceful shutdown
SIGTERM -> app -> server.Shutdown() ->
    server устанавливает флаг ->
    новые HTTP-запросы -> 503 ->
    storage.Close() -> flush на диск ->
    server ожидает завершения активных запросов -> exit

### Сохранение состояния
При *graceful shutdown* через `storage.Close()` гарантируется запись всех данных.


## Явные анти-обязанности

| Компонент     | Не делает |
|---------------|----------|
| api           | Не знает о graceful shutdown, не читает файлы, не проверяет URL |
| service       | Не работает с HTTP, не управляет жизненным циклом |
| server        | Не знает бизнес-логику, не парсит JSON |
| checker       | Не сохраняет данные, не генерирует ID |
| storage       | Не выполняет HTTP-запросы, не генерирует PDF |
| report        | Не читает файлы, не проверяет URL |
